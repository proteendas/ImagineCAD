# Architecture

ImagineCAD is a Cargo workspace of four crates with a strict dependency
direction: the GUI depends on everything, the libraries never depend on the GUI,
and `icad-core` depends on nothing but `serde`.

```
                    ┌──────────────────────────────┐
                    │  imaginecad  (binary)         │  egui/eframe desktop app + CLI
                    │  app · canvas · commands      │
                    │  ribbon · dialogs · icons     │
                    └──────┬───────────┬───────────┘
                           │           │
              ┌────────────▼──┐   ┌────▼──────────────┐
              │  icad-io      │   │  icad-vision       │
              │  DXF PDF SVG  │   │  sketch → CAD      │
              │  DWG .icad    │   │  CV + free AI      │
              └──────┬────────┘   └────┬──────────────┘
                     │                 │
                   ┌─▼─────────────────▼─┐
                   │  icad-core           │  geometry, entities, layers,
                   │  (no I/O, no GUI)    │  sheet/title block, edit ops
                   └──────────────────────┘
```

| Crate | Path | Responsibility |
|---|---|---|
| `icad-core` | `crates/icad-core` | 2D math, entity model (incl. blocks, hatches, splines, ellipses, multiline text, leaders, images), document, layers, dimension geometry, sheet + title block, hatch boundary detection, edit operations |
| `icad-io` | `crates/icad-io` | Native `.icad`, DXF 2000/R12 read/write, PDF (images, compression) and SVG plotting, DWG via the bundled LibreDWG tools or ODA |
| `icad-vision` | `crates/icad-vision` | Image → CAD: raster processing, vectorisation, beautification, label reading (any cloud provider via API key, Ollama, OpenAI-compatible, Tesseract), provider auto-detection, dimension solving |
| `imaginecad` | `crates/imaginecad` | Desktop application (eframe/egui) and headless CLI |

## 1. Core data model (`icad-core`)

### Geometry (`geom.rs`)
`V2` (f64 vector), `BBox`, `Xform` (2×2 matrix + translation, used for move,
rotate, scale and mirror) and analytic helpers: segment/line/circle
intersections, circle through three points, arc sweep maths, tessellation with
a chord tolerance. All angles are radians, counter-clockwise, arcs run CCW from
`start` to `end`, and the Y axis points up (CAD convention).

### Entities (`entity.rs`)
```rust
pub struct Entity { id: u64, layer: String, color: Color, linetype: LtRef, shape: Shape }

pub enum Shape {
    Line { a, b }, Circle { c, r }, Arc { c, r, start, end },
    Polyline { pts, closed }, Text(Text), Dim(Dimension),
}
```
`Color` and `LtRef` are either `ByLayer` or explicit (CAD Color Index / linetype).
Each `Shape` implements the editing contract used everywhere else:

| Method | Used by |
|---|---|
| `prims()` | rendering, PDF, SVG, DXF blocks, picking, bounding boxes |
| `curves()` | intersections, object snap, TRIM/EXTEND cutting edges |
| `snap_points()` | object snaps |
| `grips()` / `set_grip()` | grip editing |
| `transform(&Xform)` | MOVE, COPY, ROTATE, SCALE, MIRROR, ARRAY, paste |
| `explode()` | EXPLODE |

**Dimensions** store their defining points (`p1`, `p2`, `loc`) and an optional
text override (`<>` inserts the measured value). The measurement is
recomputed from the points every time, so editing a dimension's grips or the
geometry coordinates in the properties palette updates its value. Dimension
graphics (extension lines, arrows, text) are generated by `Dimension::prims`
using the document's `DimStyle`, scaled by the sheet scale (annotation scale).

### Rendering context and blocks
`Shape::prims(&Ctx)` receives a `Ctx` (dimension style, annotation scale, block
table). A block reference (`Shape::Insert`) expands its `BlockDef` through
`Insert::xform` (translate × rotate × scale about the base point), and
`Prim::transformed` keeps circles and arcs analytic under similarity
transforms and tessellates them otherwise. `Document::render_items` resolves
colour, linetype and lineweight per primitive, applying the layer-0 / ByLayer
inheritance rule for block contents; `snap_points_of`, `curves_of` and
`explode_entity` are the block-aware versions used by snapping, trimming and
EXPLODE.

### Curves and hatching (`curves.rs`, `hatch.rs`)
Ellipses are stored as centre + major vector + ratio + parameter range.
Splines interpolate their fit points using uniform Catmull–Rom segments, which
convert exactly to cubic Bézier and to a clamped cubic B-spline for DXF.
Hatches store boundary loops (even–odd fill). Pattern lines are clipped
analytically and solid fills are decomposed exactly into trapezoids. "Pick
internal point" builds a planar arrangement from all visible geometry (curves
tessellated, segments split at intersections, dangling edges pruned), traces
faces with a half-edge walk, takes the smallest face containing the point, and
adds the outer boundaries of other components inside it as islands.

### Primitives (`prim.rs`)
Every entity and the title block explode into a tiny set of primitives:
`Line`, `Poly`, `Circle`, `Arc`, `Fill` (arrowheads) and `Text`. The screen
renderer, PDF writer, SVG writer and the DXF dimension blocks all consume
primitives, so a new entity type only needs `prims()` to appear everywhere.
Text widths use Helvetica metrics so layout matches the PDF output.

### Document (`document.rs`)
`Document` owns entities, layers, the current layer, `DimStyle`, `Sheet`,
`ltscale` and the id counter. It provides picking (`pick`), window/crossing
selection (`select_box`), extents, and ByLayer resolution
(`color_of`, `linetype_of`, `lineweight_of`). New documents use a mechanical
template: layers `0`, `OUTLINE`, `HIDDEN`, `CENTER`, `DIMENSIONS`, `TEXT`.

### Constraints, dynamic blocks, views, markup, sheet sets (`constraints.rs`, `dynblock.rs`, `views.rs`, `markup.rs`, `arrange.rs`, `sheetset.rs`)

`constraints.rs` holds geometric constraints and named driving dimensions
over entity points (`PtRef`: line ends, polyline vertices, circle and arc
centres and ends) and segments, an expression evaluator for the driving
values, and the solver: every point of a constrained entity and every circle
radius is an unknown; a damped Gauss–Newton solve with a weak, re-anchored
pull to the current geometry meets the constraints while moving it least;
preferred points (what the user dragged) are first held exactly. The rank of
the constraint Jacobian gives the remaining degrees of freedom. `markup.rs`
has revision clouds and the bill of materials with balloon placement;
`arrange.rs` moves dimension text clear of other text and of the part;
`sheetset.rs` is the `.icadset` model. `dynblock.rs` holds dynamic block
parameters (stretch, flip, visibility, lookup) and `BlockDef::entities_for`,
which every consumer of block contents (drawing, picking, snapping, curves,
explode, export) uses to get a reference's geometry with its values applied.
`views.rs` builds section views (material intervals along a cutting line by
even–odd ray tests against the boundary curves) and detail views (curves
clipped to a circle, hatches intersected with it, then enlarged).

### Sheet and title block (`sheet.rs`)
The sheet lives in model space: its lower-left corner is `origin` and it spans
`paper_mm × scale` drawing units. Plotting therefore maps model space to paper
by `(p − origin) / scale`, which gives exact 1:N output. `Sheet::prims()`
generates the trimmed border, the frame, ISO 5457 grid reference zones and an
ISO 7200-style title block (180 × 60 mm) anchored at the bottom-right corner,
including a first/third-angle projection symbol. `fit_to()` picks the
smallest paper and the most natural ISO 5455 scale for given content.

### Edit operations (`ops.rs`)
Pure functions: `trim` (quick mode, every other object is a cutting edge),
`extend`, `offset` (lines, circles, arcs, polylines with mitred corners) and
`corner` (fillet with radius, sharp corner, or equal-distance chamfer).

## 2. File formats (`icad-io`)

See [FILE_FORMATS.md](FILE_FORMATS.md). Highlights:

- `.icad` is `serde_json` of `Document`: lossless and diff-friendly.
- The DXF writer has one code path for two versions. DXF 2000 allocates
  handles, writes owners and subclass markers, symbol tables at the
  conventional fixed handles, BLOCK_RECORDs, blocks (dimension `*D` blocks and
  user blocks) and the OBJECTS root dictionary. R12 writes equivalents for
  newer entities. The reader parses sections into group-code records and
  converts them, including block definitions, bulged polylines and hatch
  boundary paths.
- `plot.rs` resolves colours (monochrome or colour), linetype dash patterns and
  lineweights once; `pdf.rs` (hand-written PDF 1.4, Bézier arcs, WinAnsi
  Helvetica) and `svg.rs` render the resulting items.
- `dwg.rs` locates the ODA File Converter (if installed) or the LibreDWG tools
  bundled next to the executable, and round-trips through DXF 2000 in a
  temporary directory. LibreDWG is built by `packaging/libredwg/build-libredwg.sh`
  with a patch so dimension blocks resolve on DXF → DWG.

## 3. Sketch to CAD (`icad-vision`)

```
image bytes
  │ raster::load            decode, flatten alpha, grayscale, resize (≈1000–1600 px)
  │ llm::read_labels        vision model reads dimension text + boxes and describes the part ┐ optional,
  │   └ parts::PartSpec     shaft / wheel / plate / profile, validated (issues_with,        │ merged
  │                         self_check); one correction round; accepted → build, done       │
  │ ocr::read_labels        Tesseract reads printed numbers                                ┘
  │ raster::binarize        Bradley adaptive threshold + paper-relative limit
  │ raster::close/components   morphology, 8-connected components, drop text/specks
  │ raster::thin            Zhang–Suen thinning + staircase cleanup
  │ trace::trace            skeleton graph → pixel chains (endpoints, junctions, loops)
  │ fit::fit_path           Douglas–Peucker lines, Kåsa circle/arc fits
  │ part detection          components enclosing real area = part outline
  │ solve::associate        label → dimension line / edge / circle (+ leader)
  │ beautify::run           snap angles, merge collinear, align axes, weld, T-junctions
  │ align_views             projected views found as clusters, edges snapped across views
  │ solve::solve_axis ×2    1-D weighted least squares per axis, monotone mapping
  │ refine::refine          Levenberg–Marquardt over outline vertices: slanted lengths,
  │                         angles, arc radii, fillet tangency (H/V held)
  ▼
Conversion { shapes on layers, title, log, warnings }  →  pipeline::apply(doc)
```

Design choices worth knowing:

- **The AI is trusted only where it can be checked.** It reads the written
  values and may describe the part from them (a shaft, a round part, a plate,
  or a general profile in millimetres constructed from the values, never
  coordinates measured off the photo). A description is drawn only when it
  agrees with the values it read and, for a profile, when every dimension
  measures true on its own geometry. Otherwise the geometry comes from
  deterministic computer vision, which also works offline without any model.
- **Dimensions drive the geometry.** Distinct x and y coordinates of the
  cleaned sketch become "stations"; each horizontal/vertical dimension is a
  hard constraint between two stations, and undimensioned gaps are springs
  that preserve the sketch proportions. The solved stations define a monotone
  piecewise-linear map applied to every point, which preserves connectivity,
  parallelism and alignment. Contradictory dimensions that would fold the
  drawing are dropped and reported.
- **Nothing is silently discarded.** Strokes recognised as sketch annotation go
  to the hidden layer `AI-SKETCH-ANNOTATION`; strokes the pipeline is unsure about go
  to the visible, non-plotting `AI-REVIEW` layer.

`providers.rs` recognises a provider from an API key's format, verifies the
key by listing models (Anthropic `/v1/models` with `capabilities.image_input`,
OpenAI-compatible `/models`, OpenRouter modality metadata) and ranks vision
models. `llm.rs` speaks the Anthropic Messages API, the OpenAI-compatible chat
API and Ollama's API.

A detailed walk-through is in [AI_SKETCH_TO_CAD.md](AI_SKETCH_TO_CAD.md).

### Command engine
Every tool, whether started from the ribbon, the command line or a shortcut,
is a command string routed through `App::run`. Application-level commands
(OPEN, PLOT, LAYER, …) are handled directly; editing commands implement:

```rust
trait Command {
    fn prompt(&self, cx: &Cx) -> String;  // shown on the command line + cursor tooltip
    fn wants(&self) -> Want;              // Point | Select | Entity | Value | Text
    fn base(&self) -> Option<V2>;         // rubber band, ortho, '@' relative input
    fn point/value/enter/entity/selected(...) -> Flow;   // Continue | Done
    fn preview(&self, doc, cursor) -> Vec<Shape>;        // live rubber-band graphics
}
```

The canvas and command line translate raw input into these calls: clicks
become snapped/ortho-constrained points, typed text is parsed as coordinates,
a direct distance, or an option keyword. Commands mutate the document only
through `Cx`, and call `checkpoint()` before each change to push an undo
snapshot. Because commands are plain state machines they are unit-tested
without a GUI (see the `Harness` in `commands.rs`).

### Rendering
Immediate-mode: every frame the visible entities (culled by bounding box) are
converted to primitives and drawn with the egui painter. Linetypes are
rendered by dashing in screen space from world-unit patterns; lineweights
map to pixel widths (LWT toggle). The sheet is drawn in model space; the
*Layout* view simply draws white paper behind it and maps ACI 7 to black.

### Threading
The UI thread never blocks on AI: Image to CAD runs `icad_vision::convert` on
a worker thread and streams progress over an `mpsc` channel, requesting
repaints. Connection tests to AI servers are also off-thread.

## 5. Testing

- Unit tests live next to the code in every crate (`cargo test --workspace`).
- `icad-vision/src/pipeline.rs` contains an end-to-end test that renders a
  wobbly, deliberately out-of-proportion sketch and checks that the result is
  dimension-exact.
- `imaginecad/src/commands.rs` and `commands_ext.rs` drive real command
  sequences (LINE, RECTANG, TRIM, FILLET, MOVE, DIMLINEAR, HATCH with islands,
  BLOCK/INSERT, DIMANGULAR, ELLIPSE, SPLINE, BREAK, JOIN, ARRAYPOLAR).
- `icad-io/src/dxf.rs` round-trips every entity type through DXF 2000 and R12;
  `icad-io/tests/dwg_roundtrip.rs` saves and reopens DWG through LibreDWG (CI).
- The app supports `IMAGINECAD_SCREENSHOT=out.png` (and optional
  `IMAGINECAD_RUN="CMD;CMD"`) to render itself and save a screenshot, which is
  used for documentation and visual checks.
